# Student success lab demonstrations

Use Python 3.12 with the project requirements and pytest installed. Start the application with `python -m streamlit run app/main.py`.

| Lab | Exercise |
|---|---|
| 1 | Ask the coordinator to collect student information. Supply the missing ID when prompted. Reject a proposal with timetable feedback and refresh Student View to see a revision. |
| 2 | Run registered student lookup tools. The cloud simulator calculates an observed error percentage with the calculator tool. |
| 3 | Invoke the research_summary skill in Mentor labs or run `python -m app.research.research_agent`. |
| 4 | Compare the current session with persisted intervention decisions after signing in again. |
| 5 | Run `python -m app.database.seed` to initialize synthetic SQLite records. The MCP server exposes a CSV resource, a SQLite lookup, Atlas queries and a mock API. |
| 6 | Open the repository as an OpenClaw workspace with the project Python on PATH. Its skills/student-research package invokes the audited runtime. |
| 7 | Run `python -m app.workflows.node_graph` and exercise both failure paths. |
| 8 | Student View dispatches four collectors concurrently. Missing or conflicting evidence stops assessment. |
| 9 | Use Research briefing to search local project evidence and inspect the cited findings and gaps. |
| 10 | In Cloud incident inspect v2, approve rollback, and observe a fresh measurement for v1. |
| 11 | Build a release from a supported attendance-threshold requirement. Inspect boundary tests, approve, and monitor sample inputs. |
| 12 | Check mentor access, audit history, stale approval rejection and rollback to the previous rule. The lab database holds policy metadata and reviewer identifiers. |
